# 004: MOD 翻訳機能

## 目的

`.jar` 内の `lang` ファイルを検出し、`003-translation-engine.md` の翻訳エンジンを用いてリソースパックとして翻訳結果を出力する、最初のエンドツーエンド翻訳機能を実装する。出力形態が「新規リソースパック作成」で完結し、原本(JAR)を変更しないため、移植順序上もっとも単純な機能として最初に着手する。

参照: `../feature-spec.md` §6(MOD 翻訳機能)、§3(画面構成・共通 UI フロー、MOD タブ相当部分)。

## 対象範囲

### スキャン(feature-spec.md §6.1)

- `{プロファイル}/mods/` 直下(非再帰)の `.jar` を列挙する。
- 各 `.jar` から MOD ID/名前/バージョンを次の優先順で取得する: `fabric.mod.json` → `META-INF/neoforge.mods.toml`(NeoForge 1.20.5以降) → `META-INF/mods.toml`(Forgeおよび旧NeoForge) → `META-INF/MANIFEST.MF`。
- MANIFESTしかなくリソースパック名前空間に使えるMOD IDを確定できない場合は `unresolvedModId` としてスキップし、翻訳可能一覧へ含めずAPIへ送信しない。JAR内のlangパスからMOD IDを推測しない。
- `*/lang/en_us.json` または `*/lang/en_us.lang` を検出し、`lang` フォーマット(JSON/LANG)を記録する。言語ファイルが存在しない MOD は対象一覧から除外する。
- `_comment` キーや BOM・制御文字を除去してから JSON/LANG をパースする。破損ファイルは MOD 単位でスキップし、スキャン全体は継続する。
- 対象言語の `assets/{modId}/lang/{lang}.json|.lang` が JAR 内に既に存在するかを確認し、テーブルに「既存/新規」バッジを表示する(表示用の判定として常に行う)。
- テーブル列: MOD 名、MOD ID、`mods/` からの相対パス、フォーマット(JSON/LANG)、既存翻訳バッジ。

### 翻訳(feature-spec.md §6.2)

- 選択対象を MOD ID、同一ID内ではJAR相対パスのアルファベット順にソートし、決定論的な処理順にする。
- MOD IDは出力名前空間として扱い、入力JAR・翻訳結果・スキップ・失敗・サマリー・再試行の一意な識別子には `mods/` からのJAR相対パスを使う。
- 「既存翻訳の扱い」が**スキップ**の場合、翻訳直前に再確認し、既存であればスキップ件数としてカウントする。**差分更新**の場合は `003` の差分更新ロジックで不足キーのみを翻訳し、既存キーの値は変更しない。**全て再翻訳**の場合は常に全キーを対象にする。
- 全対象がスキップされた場合(または差分更新で不足キーが1件もなかった場合)、リソースパックを作成せずに終了する。
- `resourcepacks/{設定したパック名}/pack.mcmeta`(format 9)を作成し、1回の実行で選択した全 MOD を1つのリソースパックにまとめて書き込む(MOD ごとに別パックは作らない)。
- 出力: `{リソースパック}/assets/{modId}/lang/{targetLanguage}.json|.lang`(キーはソートして出力)。同じ出力パスになる選択対象が複数ある場合は、API呼び出し前に対象JARを列挙したエラーで停止する。リソースパック生成側でも重複パスを検出し、Map代入による無言の上書きを禁止する。元の `.jar` ファイルは変更しない。
- 翻訳完了後、生成したリソースパック全体をセッションディレクトリ配下にバックアップする(`logs/localizer/{sessionId}/backup/resource_pack/`)。

### MOD タブ UI(feature-spec.md §3.1〜3.2 の MOD タブ相当)

- プロファイルディレクトリ選択、スキャンボタン、翻訳ボタン、対象言語セレクタ(MOD タブ専用の選択状態)、テーブル(チェックボックス列・ソート・部分一致検索)。
- 翻訳中・スキャン中のタブ切替禁止は本仕様の範囲では単一タブのみのため、他タブとの排他制御は `008` 側で統合する前提とし、本仕様では MOD タブ単体の状態遷移(未選択→スキャン中→スキャン完了→翻訳中→完了)のみを扱う。

## 対象外

- クエスト・Patchouli・カスタムファイルのスキャン・翻訳(`005`〜`007` で扱う)。
- 進捗表示・キャンセル・ログ・履歴の横断的な UI 統合(`008` で扱う。本仕様では翻訳処理自体が進捗コールバックを呼び出せるインターフェースを持つことまでを対象とし、UI 表示は最小限のプレースホルダーで良い)。
- 複数タブ間でのディレクトリ選択共有の実装(`008` またはタブ統合時に扱う。本仕様では MOD タブ単体で完結させる)。

## 受け入れ条件

1. `mods/` 直下に `.jar` を複数配置したテスト用ディレクトリに対しスキャンを実行すると、`fabric.mod.json` → `neoforge.mods.toml` → `mods.toml` → `MANIFEST.MF` の優先順で MOD 情報が解決されることを検証する。
2. いずれの情報源からも MOD 情報を取得できない `.jar` と、MANIFESTしかなくMOD IDを確定できない `.jar` はそれぞれ区別できる理由でスキップされ、スキャン結果一覧には含まれず、ログにスキップ理由が記録されることを検証する。
3. `lang/en_us.json` または `lang/en_us.lang` を含まない MOD は対象一覧から除外されることを検証する。
4. `_comment` キーを含む、または BOM・制御文字を含む lang ファイルが正しくパースされることを検証する。
5. 壊れた JSON/LANG ファイルを含む MOD が1件あっても、他の MOD のスキャンが継続されることを検証する。
6. 対象言語の `{lang}.json|.lang` が JAR 内に既に存在する MOD には「既存」バッジが、存在しない MOD には「新規」バッジが表示されることを検証する。
7. 選択した MOD の一覧が MOD ID、同一ID内ではJAR相対パスのアルファベット順にソートされて処理されることを検証する(処理順序をログまたは出力順で確認できるテスト)。
8. 「既存翻訳の扱い」が **スキップ** の場合、既存の対象言語ファイルを持つ MOD は翻訳されずスキップ件数としてカウントされることを検証する。
9. 「既存翻訳の扱い」が **差分更新** の場合、既存の対象言語ファイルに存在しないキーのみが翻訳され、既存キーの値が変更されないことを検証する。
10. 「既存翻訳の扱い」が **全て再翻訳** の場合、既存の対象言語ファイルの有無に関わらず全キーが翻訳されることを検証する。
11. 選択した全対象がスキップ(または差分更新で不足キー0件)の場合、リソースパックが作成されないことを検証する。
12. 複数 MOD を選択して翻訳すると、`resourcepacks/{パック名}/pack.mcmeta`(format 9)と、各 MOD の `assets/{modId}/lang/{targetLanguage}.json|.lang` が単一のリソースパック配下に生成されることを検証する。
13. 出力される lang ファイルのキーがソートされていることを検証する。
14. 翻訳処理の前後で元の `.jar` ファイルの内容(バイト列またはハッシュ)が変化しないことを検証する。
15. 翻訳完了後、生成されたリソースパック一式が `logs/localizer/{sessionId}/backup/resource_pack/` 配下にコピーされることを検証する。
16. 翻訳結果・サマリー・失敗対象・再試行対象がJAR相対パスで一意に突き合わされ、同じMOD IDを持つ異なるJARが無言で同一結果へ潰れないことを検証する。
17. 同じ `assets/{modId}/lang/{targetLanguage}.{ext}` を生成するJARが複数選択された場合、API呼び出し前に停止することを検証する。リソースパック生成関数へ重複出力を直接渡した場合も例外となることを検証する。
18. `META-INF/neoforge.mods.toml` だけを持つ実物相当JARについて、スキャンからリソースパック出力まで成功する統合テストを追加する。
19. `flutter analyze` / `flutter test` が成功する。

## 移行上の判断

- 「既存翻訳の扱い」の重複チェックは、旧実装のようにスキャン時・翻訳前プレチェック・各対象の翻訳直前の最大3回ではなく、**スキャン時の表示用チェックと翻訳直前の実チェックの2箇所のみ**に整理する(feature-spec.md §4.2)。
- 差分更新モードは旧実装で未実装だった機能であり、`003-translation-engine.md` の差分更新ロジックを利用して新規に実装する(feature-spec.md §5.5、§16.2)。
- MANIFESTの存在はMOD IDの確定を意味しない。誤った `assets/unknown/` を生成してAPI費用を消費するより、理由を記録してスキップする安全側の挙動を採用する。
- 同一MOD IDの複数JARは、出力先が同じでどちらを採用すべきか自動決定できないため、先勝ち・後勝ち・自動マージは行わず翻訳前に明示的な衝突として扱う。
