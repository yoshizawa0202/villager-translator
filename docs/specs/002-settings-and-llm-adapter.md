# 002: 設定画面の基盤 + LLM アダプター境界

## 目的

設定(LLM プロバイダー・API キー・プロンプト・チャンクサイズ・対象言語)を管理する画面と、`AGENTS.md` が要求する「翻訳 API は差し替え可能なアダプター境界の内側に閉じ込める」ためのアダプター抽象を確立する。実際の翻訳呼び出し(チャンク分割・応答検証・リトライ)は `003-translation-engine.md` で扱うため、本仕様ではモックアダプターでの疎通確認までを対象とする。

参照: `../feature-spec.md` §4(設定機能)、§5.1(アダプターパターン)、§15(セキュリティ・非機能要件)。

## 対象範囲

### LLM 設定(feature-spec.md §4.1)

- プロバイダー選択: OpenAI / Anthropic / Google Gemini。
- プロバイダーごとに個別の API キーを保存する(`apiKeys: { openai, anthropic, gemini }`)。
- モデル選択はコンボボックス方式。プロバイダーごとの既定モデル一覧をコード上の定数として1箇所にまとめ、一覧にない値は「カスタム」選択でテキスト入力にフォールバックできるようにする。
- 詳細設定: 最大リトライ回数(既定 3)、temperature(既定 1.0、0.0〜2.0 の範囲チェック)。
- システムプロンプト / ユーザープロンプトを個別に編集可能。
- API キー入力欄に表示/非表示切替アイコンを持たせる。
- 「デフォルトに戻す」ボタンで全設定を初期値へリセットする。
- プロバイダー識別子は設定・アダプター・UI のすべてで `gemini` に統一する(旧実装の `"google"` / `"gemini"` 不一致を解消)。

### 翻訳設定(feature-spec.md §4.2)

- トークンベースのチャンク分割の ON/OFF。ON 時は「チャンクあたり最大トークン数」(既定 3000、1000〜10000)と「見積り失敗時にエントリ数ベースへフォールバックするか」(既定 ON)。
- 「既存翻訳の扱い」設定(既定: 差分更新)。スキップ / 差分更新 / 全て再翻訳 の3モードを選択可能にする(モードの実行時ロジックは各機能仕様で実装するため、本仕様では設定値の保存・UI までを対象とする)。
- リソースパック名(既定: `VillagerTranslator`)。
- カテゴリ別チャンクサイズ: MOD(既定 50)、クエスト(既定 1)、ガイドブック(既定 1)。範囲は 1〜1000。

### プロンプトテンプレート(feature-spec.md §4.3)

- プレースホルダーは単一波括弧 `{language}` `{line_count}` `{content}` の1系統のみをサポートする(旧実装の `{{x}}` 系との併存は行わない)。
- 既定システムプロンプト・ユーザープロンプトは旧アプリ `docs/spec.md` §7.2.0 の内容を踏襲し、行数厳守・特殊記号(`%s` `$1` `\"`)保持・`§` カラーコード保持・意訳優先のルールを含める。

### 対象言語管理ダイアログ(feature-spec.md §3.3)

- 既定言語(削除不可): 日本語(ja_jp)、简体中文(zh_cn)、한국어(ko_kr)、Deutsch(de_de)、Français(fr_fr)、Español(es_es)、Italiano(it_it)、Português-Brasil(pt_br)、Русский(ru_ru)。
- カスタム言語の追加(表示名 + 言語 ID のペア)・削除。

### LLM アダプターパターン(feature-spec.md §5.1)

- 共通インターフェース: `translate(content: Map<String,String>, targetLanguage, promptTemplate?) -> Map<String,String>`。
- `validateApiKey(key)`: 設定画面での疎通確認用(軽量な API 呼び出しで検証)。
- OpenAI / Anthropic / Gemini の各アダプターは本仕様では実 API 呼び出しを持つ骨組み(system/user メッセージ構築、temperature 反映)のみを実装し、チャンク分割・リトライ・レート制限対応は `003-translation-engine.md` に委譲する。
- テスト・UI 疎通確認用に、固定文字列を返すモックアダプターを用意する。

### 設定の永続化(feature-spec.md §15)

- API キーは Windows の資格情報マネージャー(DPAPI)を利用したセキュアストレージ、または同等の暗号化ライブラリ(`flutter_secure_storage` 等)で暗号化して保存する。
- 設定ファイル本体(JSON)には API キーを含めない。API キー以外の設定値(プロバイダー選択、モデル、チャンクサイズ、プロンプト等)は設定ファイルに保存する。
- API キーをログや例外メッセージに出力しない。

### 設定の保存タイミングの明示(#9、#11)

- 設定画面はテキストフィールドの Enter 確定(`onFieldSubmitted`)や項目変更のたびにディスク・セキュアストレージへ即時書き込む「自動保存方式」を採用していたが、次の2点が問題となった。
  - 保存が完了したことをユーザーが視覚的に確認できない。
  - 同一項目の Enter 確定に対し Flutter が `onFieldSubmitted` と `onEditingComplete` を両方発火させる場合があり、設定ファイルへの同時書き込みが競合して例外(`PathNotFoundException`)が発生することがあった。
- これを解消するため、設定画面全体を「明示的な保存ボタン」方式に変更する。
  - 各項目の変更(プロバイダー選択・モデル選択・API キー入力・チャンクサイズ・プロンプト編集・対象言語の追加削除など)は検証のうえ画面内の編集中の状態(ドラフト)にのみ反映され、この時点では設定ファイル・セキュアストレージへは書き込まれない。
  - 画面右上に「保存」ボタンを1つ設置し、押下したタイミングでドラフトの内容(設定ファイル本体・変更のあった API キー)をまとめて永続化する。
  - 保存状態インジケーターは、未保存の変更があるかどうか(「未保存の変更があります」)と、直近の保存完了時刻(「保存しました(HH:mm:ss)」)を表示する。
  - 検証エラーとなった項目はドラフトへ反映されず、保存ボタンを押しても永続化されない(既存のフィールド単位のエラーメッセージ表示と併用する)。
- テーマ切替(ライト/ダーク、feature-spec.md §3.1)は設定画面ではなくメインシェル画面のトグルから行う独立した操作であり、見た目のプレビュー性を優先して従来どおり選択と同時に即時反映・即時永続化する(本セクションの保存ボタンの対象外)。この際、設定画面で編集中の未保存ドラフト(LLM 設定・翻訳設定・プロンプト・API キー)は巻き込まず、テーマ設定のみを永続化する。
- 「デフォルトに戻す」操作は、それ自体が明示的な確定操作であるため、保存ボタンを介さず即時に永続化する(現在のテーマ設定は変更しない)。
- 未保存の変更(ドラフトが永続化済みの内容と異なる状態)がある間に設定画面を閉じようとした場合、警告ダイアログ(「保存されていない変更があります。破棄しますか?」)を表示し、「破棄して閉じる」「キャンセル」を選択させる。キャンセルすると画面に留まる。

### 翻訳実行中の設定変更の扱いの明示(#9)

- 翻訳実行中(いずれかのタブが `scanning` / `translating` 状態)でも設定画面を開いて設定を変更すること自体は禁止しない(値は即座に検証されるが、永続化は保存ボタン押下まで行われない)。
- 各翻訳フローは実行開始時点の設定のスナップショットを使用するため、実行中に保存ボタンを押して設定を確定しても、現在実行中の翻訳ジョブには反映されない。反映されるのは次回の実行からである。
- この挙動をユーザーに明示するため、翻訳実行中に設定画面を開いた場合、画面上部に「翻訳を実行中です。ここでの変更は現在実行中の翻訳には反映されず、次回の実行から適用されます。」という注意書きを表示する。

## 対象外

- 実際の翻訳結果を得るための LLM API 呼び出し(チャンク分割・応答パース・リトライは対象外、`003-translation-engine.md` で扱う)。
- MOD / クエスト / Patchouli / カスタムファイルのスキャン・翻訳 UI(`004`〜`007` で扱う)。
- 「既存翻訳の扱い」設定値を実際の翻訳フローで解釈するロジック(各機能仕様で実装する)。
- 自動アップデート(feature-spec.md §14、対象外)。

## 受け入れ条件

1. 設定画面でプロバイダー(OpenAI / Anthropic / Gemini)を選択でき、選択したプロバイダーの API キー入力欄・モデル選択欄が切り替わる。
2. モデル選択はコンボボックスに既定候補を表示し、「カスタム」選択時のみ自由入力欄が表示される。未選択・空文字のカスタム入力ではバリデーションエラーを表示する。
3. 最大リトライ回数・temperature に範囲外の値(temperature が 0.0〜2.0 外など)を入力するとエラーを表示し、保存を許可しない。
4. API キー入力欄に表示/非表示切替アイコンがあり、切替でマスク状態が反転する。
5. 「デフォルトに戻す」操作で、LLM 設定・翻訳設定・プロンプトが初期値に戻る(API キーは別途扱い、平文表示しない)。
6. 保存した API キーは平文の設定ファイル(JSON)には出現しない。設定ファイルを直接読み取るテストで、API キー文字列が含まれないことを検証する。
7. アプリ再起動後も、暗号化ストレージ経由で保存した API キーを復号して設定画面に反映できる(表示切替でマスク解除して確認できる)。
8. 対象言語管理ダイアログで、既定9言語は削除操作が無効化されている。カスタム言語(表示名 + 言語 ID)を追加・削除でき、一覧に反映される。
9. プロンプト編集欄でシステムプロンプト・ユーザープロンプトを個別に編集・保存でき、プレースホルダーとして `{language}` `{line_count}` `{content}` の3種のみが説明表示される(`{{x}}` 系は表示・サポートしない)。
10. `LlmAdapter` 共通インターフェースに対し、モックアダプターと OpenAI / Anthropic / Gemini の各アダプター骨組みが実装されており、`translate()` 呼び出しでプロバイダーごとに異なる HTTP クライアント呼び出し(または疎通確認用のスタブ)が行われることを単体テストで検証する。
11. `validateApiKey()` が、モックアダプターでは即座に真偽を返し、実プロバイダーアダプターでは軽量な API 呼び出しを1回だけ行う設計になっていることをテストで確認する(実ネットワーク呼び出しはテスト内でモック化する)。
12. 内部的に扱うプロバイダー識別子が `openai` / `anthropic` / `gemini` の3種で統一されており、設定値・アダプター選択ロジック・UI 表示のいずれの箇所にも `"google"` という識別子が存在しないことをコード検索または単体テストで確認する。
13. 設定画面で項目を変更しただけでは設定ファイル・セキュアストレージへ書き込まれない(保存状態インジケーターが「未保存の変更があります」を表示する)。「保存」ボタンを押すとまとめて永続化され、インジケーターに直近の保存完了時刻が表示される。検証エラーとなった項目は保存ボタンを押しても永続化されないことを確認する。
14. いずれかのタブが翻訳中・スキャン中の状態で設定画面を開くと、「翻訳を実行中です。ここでの変更は現在実行中の翻訳には反映されず、次回の実行から適用されます。」という注意書きが表示される。翻訳中・スキャン中でない場合は注意書きが表示されないことを確認する。
15. 未保存の変更がある状態で設定画面を閉じようとすると警告ダイアログが表示される。「キャンセル」を選ぶと画面に留まり編集内容が保持される。「破棄して閉じる」を選ぶとドラフトを破棄して画面を閉じる。未保存の変更がない場合は警告なしに閉じられる。
16. テーマ切替は設定画面の保存ボタンを介さず即時に永続化される。かつ、設定画面で未保存の編集中の値がある状態でテーマを切り替えても、その未保存の値が意図せずディスクへ書き込まれないことを確認する。
17. 「デフォルトに戻す」操作は保存ボタンを介さず即時に永続化され、現在のテーマ設定には影響しない。
18. `flutter analyze` / `flutter test` が成功する。

## 移行上の判断

- プロバイダー識別子を `gemini` に統一する(feature-spec.md §4.1、§16.2)。
- プロンプトプレースホルダーを単一波括弧 `{x}` 系に一本化する(feature-spec.md §4.3、§16.2)。
- API キーは暗号化(復号可能な形での秘匿)で保存する。ハッシュ化は LLM 呼び出し時にキー本体が必要なため採用しない(feature-spec.md §15)。
- 「既存翻訳の扱い」の実行時解釈(スキップ/差分更新/全て再翻訳の分岐ロジック)は本仕様に含めず、各機能仕様(`004`〜`007`)側で実装する。設定 UI としての値の保存・表示のみを本仕様の範囲とする。
