# 007: カスタムファイル翻訳機能

## 目的

任意ディレクトリ配下の JSON / SNBT ファイルを再帰的にスキャンし翻訳する、汎用のカスタムファイル翻訳機能を実装する。MOD/クエスト/Patchouli のような特定フォーマットの知識に依存しない、フォールバック的な翻訳経路として位置づける。

参照: `../feature-spec.md` §9(カスタムファイル翻訳機能)。

## 対象範囲

- 選択ディレクトリ配下の `.json` `.snbt` を再帰的にスキャンする。
- 「既存翻訳をスキップ」判定は行わない(常に全件が対象)。差分更新・スキップの概念自体を持たない。
- **JSON**: ネストした構造をドット/ブラケット記法のキー(例 `a.b[2].c`)へフラット化し、文字列の葉ノードのみを翻訳対象とする。翻訳後、元の構造・型・順序を保ったまま値を差し戻す(数値・真偽値などの非文字列の葉は変更しない)。
- **SNBT**: ファイル全体を1つの翻訳単位として送信する(クエストの SNBT 抽出とは異なり、`title`/`subtitle`/`description` 等の限定的な抽出は行わず、任意の SNBT を対象とする前提でファイル全体を扱う)。
- 出力先: 選択した最初の対象ファイルのディレクトリ配下に `translated/` フォルダを作成し、`{targetLanguage}_{ファイル名}` として書き出す(原本は変更しない)。

## 対象外

- MOD・クエスト・Patchouli のスキャン・翻訳(`004`〜`006` で扱う)。
- 進捗表示・キャンセル・ログ・履歴の横断的な UI 統合(`008` で扱う)。
- JSON/SNBT 以外のファイル形式への対応。
- 「既存翻訳の扱い」設定(スキップ/差分更新/全て再翻訳)の適用。本機能は常に全件翻訳とする(feature-spec.md §9 の設計方針どおり)。

## 受け入れ条件

1. 選択ディレクトリ配下の `.json` `.snbt` ファイルが、サブディレクトリを含めて再帰的にスキャンされ一覧表示されることを検証する。
2. 対象言語ファイルが既に `translated/` 配下に存在していても、常に全件が翻訳対象として選択可能であることを検証する(スキップ判定が行われない)。
3. ネストした JSON(オブジェクト・配列を含む)が、`a.b[2].c` 形式のフラットなキーに正しく変換されることを検証する。
4. フラット化後、文字列の葉ノードのみが翻訳対象に含まれ、数値・真偽値・null 等の非文字列の葉が翻訳対象から除外されることを検証する。
5. 翻訳後、フラットなキー→翻訳済み値のマップを元の JSON 構造に差し戻すと、元の構造・キー順序・非文字列値がすべて保持されることを検証する。
6. SNBT ファイルがファイル全体で1つの翻訳単位として LLM アダプターに渡されることを検証する。
7. 複数ファイルを選択して翻訳すると、`{最初の対象ファイルのディレクトリ}/translated/{targetLanguage}_{ファイル名}` として出力され、元のファイルは変更されないことを検証する。
8. 同名ファイルが異なるサブディレクトリに存在するケースで、出力ファイル名の衝突が発生した場合の挙動(上書き/エラー/リネーム等、実装時に決定する方針)が一貫していることを検証する。
9. `flutter analyze` / `flutter test` が成功する。

## 移行上の判断

- 本機能は原本を変更しない出力方式のため、追加のバックアップは不要とする(feature-spec.md §12)。
- 「既存翻訳をスキップ」判定を持たない設計は旧実装の方針を踏襲する(feature-spec.md §9)。
- スキャン時、出力先である `translated/` ディレクトリ配下は除外する。前回実行の出力ファイルを次回スキャンで翻訳元として再検出してしまうことを避けるための実装上の判断であり、「既存翻訳をスキップしない」方針(常に全件が対象)とは独立した、スキャン対象そのものの絞り込みである。
- JSON・SNBT のいずれも、クエスト翻訳(`005`)と同様にファイル単位を1つの翻訳単位として LLM アダプターへ渡す(ファイル内でのキー単位のチャンク分割は行わない)。本機能は「既存翻訳の扱い」設定を持たない単純なフォールバック経路であるため、MOD 翻訳(`004`)のようなチャンクサイズ設定は適用しない。
- 受け入れ条件8(出力ファイル名衝突)の方針: 選択ファイルを相対パスの昇順で決定論的に処理し、`{targetLanguage}_{ファイル名}` が既出の場合は拡張子の前に連番(`_2` `_3` ...)を付与して一意化する(上書きによるデータ消失を避けるため)。「選択した最初の対象ファイルのディレクトリ」(受け入れ条件7)も同じ相対パス昇順で決定する(UI 上のクリック順など非決定的な要素に依存しないため)。
